# 导读与注释示例

本页只说明写法，不规定成品目录、概念数量或文件覆盖率。下文的尖括号是占位符，实际交付必须换成已核实的文件和符号。

## 代码树：真实目录层级加职责

不够有用：

```text
src/        源代码
tests/      测试
config/     配置
```

更有用（占位符仅示意排版，交付时换成真实路径）：

```text
<仓库>/
├─ <应用目录>/
│  ├─ 【重要】 <入口文件>.py   解析配置并选择实际运行路径
│  └─ <配置文件>.py          定义可选任务和默认值
├─ <核心目录>/
│  ├─ 【重要】 <执行文件>.py   推进核心状态并产出结果
│  └─ <数据文件>.py          把输入转换为执行对象
└─ <测试目录>/               核对状态与输出契约
```

`【重要】` 只标跳过后难以理解主机制或结论的文件；未标记不代表无用。若仓库有多个独立入口，在树中分别保留其真实位置，再用文字说明它们怎样共享模块。树负责定位文件，调用箭头与时序留给数据流部分。

## 开头：先说项目做什么

不够有用：

> 本文对应当前分支、提交号和工作区修改；读前请区分入口与证据边界。

更有用：

> 这个项目把输入数据交给核心程序处理，并记录结果。另一条流程读取这些结果，判断是否需要更新规则。下文先说明两个入口，再跟一次实际执行。

这里示意的是叙述顺序，不是可套用的项目定位。实际开头要说出目标仓库的对象和行为；版本、未验证条件等放到核查说明里。

## 概念：只解释会阻碍读代码的契约

不够有用：

> Batch 是一组样本。缓存可以提高速度。

更有用的写法应包含四件事：代码里它叫什么；输入输出或状态是什么；转换或时序是什么；读错会导致什么结论。必要时用一组已核实的小数据说明边界值，并指向真正负责转换的函数。

不同领域也采用同一选择标准：只解释会改变读者对输入、状态、控制流或结果判断的概念。具体结论必须核对目标仓库的实际实现。

## 数据流：先总览，再跟一次真实执行

总览先分清各条路径，而不是把独立入口接成一条长链：

```text
<交互入口>：任务 → 执行器 → 结果
<批处理入口>：配置 → 单次执行 → 记录 → 汇总/评测
<服务入口>：请求 → 工作进程 → 响应（仅在批处理实际调用它时画连接）
```

再挑一条代表性路径，画出关键分支和回到下一轮的状态；输入、真正发生的副作用和记录应容易找到。必要时单独画跨回合的训练或评测流程。每张图保持在读者能一眼看清的规模，紧邻文字再交代具体函数、参数和其他实现的差异。若训练和推理或在线执行和离线评测并不直接相接，就不要靠排版暗示它们是同一次调用。图中的箭头不能只凭模块名称推断。

## 阅读路线：让每站回答一个问题

不够有用：

> 先读 `main.py`，再读 `model.py`，最后读 `tests/`。

更有用：

> 在 `<入口文件>::main` 确认哪份配置选中了当前实现；再到 `<核心文件>::forward` 追输入如何变形；最后到 `<评测文件>::evaluate` 核对结果使用的是哪个输出。读完应能回答“评测的量是否就是训练优化的量”。

文件和符号必须在目标仓库真实存在；示例中的占位名不能出现在成品里。

## 注释：解释局部机制，架构留给导读

不够有用：

```python
# 遍历记录
for row in rows:
    ...
```

更有用：

```python
# 先按规范化主键去重；原始显示名可能有别名，直接用它会重复计数。
for row in unique_by_key(rows):
    ...
```

真实注释必须由实际调用链证实。文件头若确有必要，只用简短文字交代该文件接收什么、产出什么和应先看哪个函数；不要在源码顶部重复整张架构图。已有注释或 docstring 足以解释契约时，不再添加同义文字。

核心长函数可像阅读路线一样给出局部路标，再在关键分支解释“数据是什么、何时改变、为何不能按直觉处理”；路标对应真实阶段，不规定阶段数：

```python
def build_index(...):
    """校验输入记录，构建索引，并返回冲突报告。"""
    # 先校验主键；后续合并依赖这里固定的身份。
    ...
    # 同一主键有多个版本时按版本字段选择，不能按文件顺序覆盖。
    ...
    # 写入已通过校验的结果；被拒记录只进入冲突报告。
```

这只是排版示例，步骤、数值和判据都要按目标仓库核实。测试或边缘文件若与主线有关，一句说明其验证的契约即可；与问题无关的文件不用加注释。

## 成品自检

- 读者能用代码树找到入口和关键模块，而不会被无关文件淹没。
- 每个入选概念都解决一个具体的源码理解障碍。
- 数据流中的关键箭头能对应真实调用、对象传递或状态写入。
- 导读解释跨文件关系；新增源码注释解释邻近代码的非显然语义。
- 运行、测试和研究结论的证据等级被准确表达。
